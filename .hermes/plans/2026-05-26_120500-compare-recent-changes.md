# Plan: Compare Recent Changes in Deriv Project Using File History

## Goal
Create a process to identify and compare recent modifications in the Deriv trading‑bot repository without relying on Git. The comparison should highlight what was changed in each file and point out any missing backup versions.

## Current Context / Assumptions
- Project root: `/home/salmarina/deriv`
- The most recently touched files are listed in `temp/last_changes.txt` (generated by the agent).
- Only `index.html` has an explicit backup (`index.html.bak`). Other files may not have a historic copy.
- The environment provides standard Unix tools (`diff`, `stat`, `find`).
- No version‑control history is to be used.

## Proposed Approach
1. **Read the list of recent files** from `temp/last_changes.txt`.
2. **For each listed path**:
   - Determine if a backup/older copy exists (`*.bak`, `*.old`, `_old` suffixes) in the same directory.
   - If a backup exists, run a unified diff (`diff -u`) between the backup and the current file.
   - If no backup exists, retrieve the previous version using the file's modification timestamp:
     * Use `stat -c %Y <file>` to get the epoch of the current file.
     * Search the filesystem for a file with the same name that has an *earlier* timestamp (rare but may exist in `temp/` or other archival folders).
3. **Collect diffs** into a single markdown report under `temp/recent_changes_report.md` for quick review.
4. **Summarize** each diff with a short description (added/removed lines, changed logic, UI updates, etc.).
5. **Flag** files lacking any historic counterpart so the user knows a manual review may be required.

## Step‑by‑Step Plan
1. **Load recent‑files list**
   - `read_file` → `temp/last_changes.txt`
2. **Iterate over each entry** (shell loop or a short Python script) and:
   - Extract the absolute path.
   - Search for a backup via `find $(dirname $path) -maxdepth 1 -type f \( -name "$(basename $path).bak" -o -name "$(basename $path).old" -o -name "$(basename $path)_old" \)`
   - If found, run `diff -u <backup> <path>` and capture output.
   - If not found, attempt a timestamp‑based fallback:
       * List all files with the same name in the project (`find /home/salmarina/deriv -type f -name "$(basename $path)"`).
       * Sort by modification time and pick the one *just before* the current file.
       * Diff against that version if it exists.
3. **Aggregate results**
   - Append each diff to `temp/recent_changes_report.md` with a markdown header `## <path>`.
   - Add a note if no historic version was located.
4. **Create a concise summary** at the top of the report:
   - Number of files compared.
   - Files with missing history.
   - Highlight major UI changes (e.g., differences in `index.html`).
5. **Deliver the report** to the user (path provided) and optionally open it in the browser (`npm run dashboard` will show the UI, but the diff is a plain text file).

## Files Likely to Change / Review
- `index.html` (has `.bak` – primary UI diff)
- `backend/server.js`
- `js/app.js`
- `js/config.js`
- `backend/strategies/Engine.js`
- Any script under `temp/` that was recently regenerated.

## Tests / Validation
- Verify that each `diff` command exits with status `0` or `1` (no differences vs differences).
- Ensure the generated markdown file is well‑formed and readable.
- Spot‑check a few diffs manually to confirm the script captured the correct content.

## Risks, Trade‑offs, Open Questions
- **Missing backups**: Most files lack explicit historic copies; the timestamp fallback may still not locate a prior version.
- **Large diffs**: Very big files could produce massive diff output; consider truncating to the first 200 lines with a notice.
- **Performance**: Scanning the whole project for each file is O(N²). The plan restricts searches to the same directory first, then a shallow global search if needed.
- **User expectations**: Clarify whether the user wants a full diff or only a summary; the plan produces both.
