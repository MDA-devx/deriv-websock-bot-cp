# Plan: Search for TODOs in the Deriv project

## Goal
Identify actionable TODO/FIXME/HACK/XXX markers in the `/home/salmarina/deriv` codebase and produce a prioritized cleanup path.

## Current context / assumptions
- Project is a lightweight HTML/JS/CSS + Node backend workspace.
- Plan mode is active: planning only, no implementation changes.
- A preliminary repository-wide scan for TODO-style markers was run.
- Current scan result: no real TODO markers found; one false-positive-like match in `package-lock.json` due to `XXX` appearing inside a checksum string.

## Proposed approach
Use a two-pass discovery process:
1. High-signal keyword scan with strict word boundaries to avoid hash/noise matches.
2. Targeted follow-up scan in likely source paths (frontend/backend JS/HTML/CSS) to avoid lock/vendor artifacts.

If TODO markers are found, classify each by urgency and ownership, then translate into implementable tasks.

## Step-by-step plan
1. Re-run TODO search with case-insensitive word-boundary regex:
   - `(?i)\b(todo|fixme|hack|xxx)\b`
2. Scope a follow-up scan to source files only (e.g., `*.js`, `*.html`, `*.css`, `*.md`) and exclude generated/lock files.
3. For each true match, capture:
   - file path
   - line number
   - exact note text
   - inferred intent (bug, tech debt, feature, cleanup)
4. Create a normalized TODO inventory table.
5. Prioritize items (P1/P2/P3) by risk and user impact:
   - P1: runtime correctness/security/data integrity
   - P2: maintainability/performance
   - P3: style/docs/low-risk refactors
6. Convert inventory into an execution backlog:
   - one actionable task per TODO cluster
   - include acceptance checks and tests
7. Validate no TODO markers remain unresolved after implementation (future execution phase).

## Files likely to change (execution phase, not in this plan step)
- `frontend/js/**/*.js`
- `frontend/**/*.html`
- `frontend/**/*.css`
- `backend/**/*.js`
- Documentation files (if TODOs are docs-related)

## Tests / validation
- Re-run TODO scan and confirm zero unresolved markers or document intentional TODOs.
- Run frontend manual smoke checks (chart load, websocket flow, signal rendering).
- Run backend startup/smoke test for `backend/server.js` behavior.
- If TODOs touch indicators, verify outputs for SMA/EMA/RSI/BB paths.

## Risks, tradeoffs, open questions
- Risk: TODOs may be absent but debt exists in comments/issues outside code.
- Tradeoff: strict keyword scanning minimizes false positives but can miss non-standard note formats.
- Open question: should external dependencies/lockfiles be permanently excluded from TODO policy checks?
- Open question: do you want TODOs preserved (tracked debt) or removed (issue-driven workflow only)?
